# E5 手动主机＋外部 5V 受电试验

## 范围和依据

E5 首轮仅由 `devices/e5/prepare-kernel.py` 接入；其后公共实现提取到
`devices/common/musb-host-sink.py`，T551M 显式启用同一 MUSB 路径，见
`docs/T551M-HOST-SINK-20261022.zh-CN.md`。T512N 后续在自己的准备器
显式接入，见 `docs/T512N-HOST-SINK-20261022.zh-CN.md`；M8、K1 与远航 41S
的内核准备路径不随此次提取改变。网页与屏幕继续使用已有的能力检测，只有
内核提供 `usb_host_sink_supported=1` 时才显示“主机＋外部供电（实验）”。
不提供该模式的开机自动应用，重启仍恢复原有自动策略。

依据是所连 E5 自身的运行设备树与实际驱动，不套用 41S 的 DWC3 配置：

- USB 控制器为 `sprd,qogirn6lite-musb`；其两个 extcon 都指向 UMP9620
  Type-C `@380`。Type-C 自身的 extcon 指向真实 VBUS GPIO。
- PHY 为 `sprd,qogirn6lite-phy`，充电芯片报告型号 AW32257。
- 复用固定内核基线 `020b970e351eee3887e6caaf2d653926e7086e44` 以及已有
  E5 适配；本次没有变更设备树、充电电流表、原厂固件、AT 或 NV。
- 这是用户选择的额外手动模式，不声称原厂 Android 已提供相同行为。

## 实现

1. 手动策略使 CC 保持受电端，单独记录数据主机请求，不伪造 USB-HOST
   extcon 事件。切回其他策略仍走原有 CC 切换流程。
2. MUSB 同时检查实际外部 VBUS、CC 接入、PHY 的供电存在状态以及 BC1.2
   检测完成，满足后才请求主机。外部电源和充电完成通知驱动已有工作队列，
   没有增加常驻轮询服务。
3. 外部受电会话不调用本机 boost enable/disable，保留 PHY 对真实充电插拔
   的处理；数据主机不会把这类会话误标成应停止充电检测的普通供电 OTG。
4. 开始外部受电会话时，若本机升压仍开启或状态读取失败，则拒绝进入。
   普通主机启用升压前也复核实际外部电压，避免角色切换竞态造成反向供电。
5. 拔出外部电源、撤销手动策略或检测条件消失后，移除主机总线并退出此会话。
   从旧供电主机切换时先完成退出，再进入受电主机。
6. 提供实际数据主机状态给共享 USB 后端。E5 当前未注册标准 Type-C class
   端口，因此验证采用控制器总线、真实 VBUS、升压 regulator 和充电接口，
   不伪称读取到了 `port0/power_role`。
7. AW32257 原驱动把 PHY 通知的电流预算是否为零当作在线状态；BC1.2
   未识别时，这与实际外部供电不等价。仅在手动受电主机会话中，额外以真实
   VBUS、CC 和检测完成状态判断电源在线；开始/退出会话通知已有充电管理。
   保留 UNKNOWN 分类，不伪装 SDP/DCP，也不直接强制打开 CE 或写电流。
   原设备树的 `charge-unknown-current-microamp` 为 1650000/1650000 µA；
   由现有 charger-manager 使用该行与温控表，用户停充/限充仍由原路径控制。

## 已验证

- 编译完整 E5 Image 与配套模块；保留原启动参数、动态 Linux/Android 槽位、
  initramfs 的其他内容和诊断尾部。启动镜像写入与回读校验通过，Android
  boot 完整 SHA-256 写入前后保持一致。物理 NV 未写入。
- 新启动后 NCM 可用、蜂窝 WAN 获取 IPv4、热点和充电状态正常，没有发现
  BTF 校验失败或未知符号。未将这些检查等同于长期无线稳定性测试。
- 借电脑 USB 的实际 5V 进行十秒对照：每秒读取均为 `policy=host-sink`、
  `role=host`、主机根集线器 `usb1` 存在、`status=Charging`、`vddvbus=disabled`。
  电池侧电流为正值约 51–188 mA；它不是 USB 输入电流。
- 对照后恢复 `auto`，主机根集线器移除，NCM 重新连接；没有保存临时策略。
- 实际 C 代码回归覆盖充电检测尚未结束、CC/外部 VBUS 消失、策略撤销、
  旧供电主机退出、HOST_IDLE 接续、用户数据禁用，以及升压已开启、读取错误、
  角色采样后断电、外部供电存在和正常 OTG 升压失败。
- 已有根集线器生命周期及 BC1.2 重启回归通过；共享 USB 后端的能力过滤、
  角色异步确认和拒绝该模式开机保存的回归通过。

## 实际扩展坞首轮结果及后续修正

用户首轮确认网口可用，但没有充电。该轮日志显示 RTL8153 已由 r8152 枚举，
BC1.2 多次检测均为 UNKNOWN，充电驱动报告 online=0，电池仍放电约 0.4 A。
不能把前述电脑供电对照当成扩展坞充电已经成功。

后续按第 7 点补充实际电源在线判断，新增 C 回归检查：未知类型且真实外部
受电时 online=1；退出手动会话、VBUS 消失、未检测完成、PHY 报断电或缺失
供电提供者时不借此报告在线；原有 SDP 分支保持不变。该版完整内核/模块
已编译、热部署并正常下发重启，Android boot 哈希仍不变。当时其他机型尚未启用此实现；后续 T551M 接入见上述独立记录。
不以这些短时检查推断最大充电电流或长期稳定性。

## 第二轮实际扩展坞通过

用户明确反馈网口与充电同时可用。读回日志确认同一轮：

- 开机 82.38 秒进入 `external=1` 的主机，83.84 秒 RTL8153 网卡注册成功。
- 95.31 秒的原有充电日志为 `chg_sts:1`、电池净电流 **+1107 mA**，
  电池充电设定为 1612 mA，输入预算为 1650 mA；类型仍为 UNKNOWN。
  输入预算不是 USB 电流表测量值，1612 mA 是 AW 寄存器量化后的设定。
- 100.82 秒退出主机并移除网卡；接回电脑后恢复 `auto/device`、NCM 和
  SDP 原有 500 mA 输入预算，蜂窝 WAN 仍为 up，没有未知符号或内核异常。
- 实际部署完整 boot SHA-256 为
  `65514aa9e2178b69fa1fef9ecb5b91c82bee3ec110505d29d559dd3b7f1bb7bf`，
  完整根模块包 SHA-256 为
  `53b3d8ba15f5893a0d7296a5d3155b4a4108dc404ceb7420d1a51992a47325f8`。

本轮确认这个 E5 与这个扩展坞组合能够同时充电和通信。长期负载、多轮拔插、
其他扩展坞、主动限充期间的该组合和其他机型仍未实物验证，不扩大结论。

本次不制作发布安装包。私有设备备份和原始回执保存在忽略的
`work/e5-host-sink-20261022/`，不提交设备标识或原始配置。
