# M8 手动主机与外部供电（2026-10-22）

## 范围与原厂依据

本机 VIPME M8 为 UMS9620，实际 USB 控制器是 25100000.dwc3；沿用本机
原厂设备树、M8 BQ2560x 充电适配及 4.25 V 充电电压策略。升压 regulator
为 I2C6 0x6b 的 vddvbus。不能将备用 MUSB 节点或其他机型的充电参数套入。

M8 准备器仅在 recipient=m8 时显式接入公共 DWC3 host-sink 和 legacy CC
策略扩展；K1 保持自己的显式入口，41S 保持自己的 CC 策略及原有 API。
实际 CC/VBUS/PHY 检测与充电完成通知驱动角色切换，没有新增常驻轮询服务。
外部供电主机不启用本机升压，普通主机保留升压，退出恢复原选择。
不伪装 DCP、不提高 UNKNOWN 电流、不修改温控、AT、回放或 NV。

## 软件和部署验证

复用既有 M8 独立补丁层和对象缓存，固定构建入口编译完整 Image 和 234 个
匹配模块；公共 DWC3 七项回归、FGU/JEITA 与模块配套检查通过。

实机确认动态 Linux 槽为 B、Android 为 A，仅替换 Linux 内核和所有早期／
根文件系统配套模块，保留 initramfs 其他内容、启动参数和诊断尾部。
备份时发现旧 boot 的 AVB footer 仍指向 39219200，但实际载荷末尾为
39220540、AVB0 位于对齐后的 39223296。此次只在诊断重封装中依据实际
AVB0 修正位置记录，保留原始镜像和有效 footer 备份；没有更改全局校验规则。
写入后回读通过，Android boot SHA-256 未变化。

部署 boot SHA-256：`29eb2b72377f3574182d65bf1b7810a7bf4473ace1ef23d88be5c38bf5b66cbd`。
根模块包 SHA-256：`cabc35e9659870b5e923cc6fbec83e235737dc0bb3cf6a667c87b01549e3b541`。

重启后内核为 6.18.54-m8-probe12 #2；USB 后端报告 auto/device、NCM 及
host-sink 能力，无待完成任务和错误；基带对象正常出现。充电电压上限仍为
4250000 µV。

## 三种模式实物通过

用户确认自动 OTG、手动主机、主机＋外部供电均正常。当前日志可交叉确认：

- 107.72 秒自动进入 host boost=1 external=0，RTL8153/r8152 网卡枚举并
  加入 br-lan；普通主机由本机供电。
- 160.44 秒退出；177.20 秒进入 host boost=0 external=1，178.95 秒网卡
  再次枚举。该外部供电会话电池状态为 Charging，输入预算 1000 mA，电池
  接口净电流 +334～756 mA；这些数值不等同 USB 电流表实测。

  网卡再次正常枚举，表明外部供电会话退出没有阻断普通 OTG。
- 230.97 秒回到 device boost=0 external=0，接回电脑后为 auto/device、
  NCM，基带对象存在，后端无待完成任务或错误，充电恢复 SDP 500 mA 预算。
