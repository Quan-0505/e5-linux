# 热点名称和密码恢复初始值：确认项与修复范围

用户报告 E5 更改热点名称、密码，隔夜又恢复安装时配置；未取得该设备的日志，
不能据此确认是否重启、更新、触发 LuCI 应用回滚，或文件系统保存失败。
仓库公共服务未发现定时重置 SSID/密码的任务。

已确认的源码风险位于 `openwrt/overlay/etc/uci-defaults/91-e5-wireless`：
只要 `configured.wireless` 标记不存在，即使已经有自定义无线配置，也会再次使用
`install.conf` 覆盖 SSID/密码；旧入口还会在 UCI 保存失败后继续创建“已配置”标记。
这些是入口的确定行为，不等同于已证明群友此次隔夜恢复的根因。

公共修复覆盖所有 E5 仓库机型：

- 已有初始化标记时直接退出，不重新读取安装凭据。
- 标记缺失但存在自定义 AP、STA 或 mesh 配置时，保留现有配置。
- 仅没有接口或仍为未启用的 `OpenWrt` 开放模板时导入安装参数。
  模板字段已对照连接 E5 的 `/lib/wifi/mac80211.uc`，兼容 radio 没有 disabled 字段。
- 有尚未提交的 UCI 变更时，不替用户提交，也不写“已配置”标记。
- batch、字段设置、commit 或标记写入失败时明确返回失败，保留初始化入口供后续重试。
- 不修改 LuCI 的连接确认及自动回滚行为，不增加轮询或定时重写配置。
