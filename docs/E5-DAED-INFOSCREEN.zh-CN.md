# E5 信息屏 DAED 适配

E5 的小屏保留原生信息屏界面，不嵌入完整 DAED 管理站。DAED 信息屏应用 1.4.7 显示运行状态、实时上下行速率与累计流量，并提供单键启停、重载配置和更新订阅。速率数值可在 bit/s 与 byte/s 间切换。需要登录 DAED 时，屏幕显示一次性二维码；手机连接 E5 Wi-Fi 后扫码，在手机页面填写 DAED 账号密码。设备只保存受权限保护的登录令牌，不保存明文密码；令牌有效期遵循 DAED 的 30 天会话期限。

在信息屏“设置 → 快捷按钮”中，可以分别为实体数字 `0` 到 `9` 选择默认操作、关闭、DAED、电话，或概览/信号/流量/短信/热点/设备/详细信息/设置/应用列表。默认操作保留原有习惯：`0` 打开 DAED，`1–9` 切换原页面。映射保存在 E5 的 `/etc/config/e5-infoscreen`，选择后立即生效并跨重启保留。应用已打开时不会重复刷新；目标应用未安装时屏幕提示用户。主程序先处理按键锁和息屏状态，因此快捷键不会解锁或唤醒息屏设备；电话通话进行中也不会抢占实体按键。

DAED 插件、二维码配对后端和升级保留逻辑位于本仓库 `openwrt/infoscreen-plugins/daed/` 与固件安装代码中。信息屏核心固定为 `ci/infoscreen` 的 gitlink 版本。构建 OpenWrt 根文件系统时，`tools/patch-e5-daed-shortcut.py` 将快捷按钮设置类别、UCI 状态读取及数字 `0–9` 按键路由应用到暂存的核心文件，不需要维护第三方信息屏 fork。若上游核心调整按键处理代码，补丁会因锚点不匹配而让构建失败，要求先适配并验证再更新上游锁定版本。

回归检查 `python3 tools/tests/infoscreen-daed-key0.py` 从固定 gitlink 的原始文件开始，验证补丁唯一应用、快捷键设置 10 项与目标选择、JavaScript 语法、息屏/按键锁保护顺序和重复应用行为。`python3 tools/tests/infoscreen-daed-app.py` 检查 1.4.7 页面、流量接口、DAED 屏幕控制、配对后端及升级保留逻辑；完整发布工作流另运行信息屏浏览器和设备侧检查。

2026-10-19 的 E5 OpenWrt 实机验证中，设置接口返回了 0–9 共 10 个键位及各自目标；临时将数字 6 设为 DAED 后，状态接口读回 `app:daed`，清除测试值并重启信息屏后恢复为默认。信息屏服务、Cog 和本机 API 均正常，设备实际提供的 `app.js`、`mobile.js` 与部署哈希一致。自动化回归覆盖了页面/应用路由和按键锁、息屏保护；本次未逐个远程按压实体 0–9 按键，也未将完整新固件刷入 E5。

2026-10-24 的 E5 实机恢复验证确认：固件原带的 1.3.2 页面缺少流量卡片；恢复为 1.4.7 后，DAED 状态、`/traffic` 接口和新的小屏布局均正常显示。随后重启信息屏服务，DAED 仍保持运行。完整新固件仍需从本次源码构建并验证后再发布。

固件不包含个人订阅、节点、DAED 账号密码、配对令牌、数据库、设备身份或 NV 数据。
