# MU300 短信问题的 E5 扩散核对（2026-10-22）

群友报告 MU300 clean-tf-7.2 原生服务与面板分读不同短信池，以及 25 字符
带时区时间超出 21 字符列导致预览错位。MU300 仓库已统一原生生产者、
面板和转发的目录解析，并修正列表识别及文本 JSON 转义。

E5 公共实现不受这两处缺陷影响：收件通过 e5-sms-receive 写入
/etc/e5-sms/inbox.json（支持原有 E5_SMS_DATA 配置），e5-sms 聚合结构化
JSON，t551m-sms 直接投影 time/text 字段；没有 MU300 的目录存在性回退，
也没有把 CLI 的固定列当成 JSON。屏幕与网页已读操作仍作用于同一收件池。
未照搬 MU300 目录或解析器，不修改 E5/其他机型的接收、AT、NV 或回放。

强化既有 dual-sms.py 的共享网页/屏幕未读用例，加入双卡列表、完整带时区
时间，以及中文、引号、反斜杠、制表符预览的断言；通过真实本地 JSON 收件
持久化和网页适配器串接验证，无 AT 或外部短信请求。

WSL 下 dual-sms.py 20 项、sms-multipart.py 14 项、dual-sms-send.py 3 项
均通过。没有把本地夹具测试称为中国广电卡实物收件验证；此次没有编译、
打包、提交或部署短信修改。现有 USB 主机与外部供电工作区修改保持原样。
