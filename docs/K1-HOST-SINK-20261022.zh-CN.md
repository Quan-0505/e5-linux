# K1 主机＋外部 5V 受电适配

## 本机依据

原厂固件 `AngelCare.K1.YUAN.YD.T1.0`，Android 13 / 5.4.210，系统构建
`aa08072233`、vendor `aa08080151`；原机模块及 DT 依据见
`ANGELCARE-K1-ASSESSMENT-20261020.zh-CN.md` 和 `devices/k1/README.md`。

本轮运行设备的 UDC 是 `25100000.dwc3`，父节点
`/soc/ipa-apb/usb3@25100000` 为 `sprd,qogirn6pro-dwc3`。两个 extcon 是
0x116（真实 VBUS GPIO）和 0x64（Type-C @380），供电 regulator 为 phandle
0x227，两个 PHY 为 0x50/0x51，使用实际组合 PHY usb-phy[1]。
另一个 `/soc/aon/usb@a00000` 是备用 MUSB 节点，不能据其存在套用 T551M
的 MUSB 适配；实际运行 UDC 和角色路径已交叉核对。

## 实现及边界

- 从已验证的 41S 实现提取 `devices/common/dwc3-host-sink.py`，共用 DWC3、
  真实 VBUS 和组合 PHY 的状态切换。41S 用自己的 ABI 调用公共实现，保留
  它的专属 CC 策略；不把 41S 的电池、功放、显示或其他设置带到 K1。
- K1 显式启用公共 DWC3 手动策略扩展。M8 随后在自身入口显式接入，并单独部署；需要独立实物
  验证。MUSB 型号的接入路径不变。
- K1 保留本机 BQ2560x 的 REG0E 电压编码、4380 mV 上限（向下量化到
  4376 mV）、原有电流编码及本机 JEITA/OCV。没有修改温控或校准参数。
- 外部供电模式只请求数据主机，CC 保持受电；真实 VBUS、CC、PHY 电源状态
  与 BC1.2 检测完成缺一不可。本机升压不开启，不虚构 PD 或充电器类型。
  普通 OTG 仍通过真实 Type-C HOST 事件开启供电；退出和错误释放沿用控制器
  和 notifier 的实际生命周期，不增加常驻轮询。
- 网页、屏幕沿用公共能力检测。实验模式不允许开机保存，重启默认恢复自动。
  原 AT owner、回放、上网卡和 NV 路径没有改动。

## 扩展坞电流偏低的只读核对

用户指出 41S 与 K1 受电主机时充电电流较小。本轮不改参数，核对得到：
K1 实机运行 DT 的 UNKNOWN 电流对为 1050000/1050000 µA，硬件量化后输入
上限为 1000 mA、充电设定 990 mA；受电主机日志仍为 UNKNOWN。41S 的原厂
DT 各电池节点 UNKNOWN 对均为 1000000/1000000 µA，既有实测为输入
1000 mA、充电设定 960 mA。两者均沿用原厂未知电源档，并非共用代码新增了
固定 1 A 常量。

K1 扩展坞测试时电池净电流约 +487～589 mA，包含设备/网卡同时运行后的
剩余充电量，不能与 USB 输入预算直接比较。设备侧报告 VBUS 约 4.58～4.59 V；
是否存在限制进一步加流的真实压降需要电流表/电源对照，不能仅凭该值定论。
本轮未伪装 DCP、修改 UNKNOWN 表、提高电流或关闭温控。
