# 分卡射频开关改为原厂 SFUN 流程

日期：2026-10-19。公共实现用于 E5、T551M、M8、T512N，网页和实体屏幕共用后端。

## 证据与问题

- 用户本轮实测：`CFUN? → 1`，`SFUN=5 → OK`，`CFUN? → 0`；随后 `SFUN=4 → OK`，`CFUN? → 1`。用户没有在这段记录中注明机型或固件版本，不能推断所有固件的应答时延。
- 本地原厂 E5 `libimpl-ril.so`，SHA-256：`c0e86a5a6d7402a3d126e411fdb956deb8a6454763d55505c3ba64f839d0c14b`。二进制来自既有原厂提取，完整固件版本未在本轮重新核实。射频控制函数 `0x415d0..0x41f20` 引用 `SFUN=5` 和 `SFUN=4`（另含带参数的开启命令及固件不支持时的无参数分支）。
- 该二进制 `isRadioOn`（`0x29cf0..0x29dbc`）读取 `CFUN?`，把 0、2 判为关闭，1 判为开启。既有原厂 RIL 对照源码的 `requestRadioPower` 也使用 `SFUN=5/4`。二进制行为与用户实测相符。
- 旧代码使用 `CFUN=4/1`，之前只验证了对应数值变化和设置保存，没有证明等同原厂的无线电关闭状态。这次修正命令本身，不改 UI 文案来掩盖差异。

## 修改

1. 独立开关通过原有 AT owner 发送：

   ```text
   AT+SPACTCARD=<0|1>;+SFUN=5
   AT+SPACTCARD=<0|1>;+SFUN=4
   AT+SPACTCARD=<0|1>;+CFUN?
   ```

   SIM1 对应 0，SIM2 对应 1。关闭回读接受 0 或 2，开启要求 1；不能只凭 OK 成功，也不把旧飞行模式值 4 当作 SFUN 关闭已确认。
2. 同步修改 ModemManager 的冷启动策略恢复、热初始化策略执行和电源启停接口。没有保留另一套 CFUN 写入作为后备。
3. `CFUN: 0` 不再一律意味着 SIM 已掉电：恢复时查询现有 SIM 状态；SIM 仍有供电时直接 `SFUN=4`，明确未供电时才进入既有初始化。查询失败或忙不能触发盲目重置。
4. 初始化遇到本卡为 0 时读取另一栈；若另一栈已为 1，仅恢复查询卡槽并执行保存的禁用策略，不重做另一栈的 SIM 上电、模式配置或回放。两栈都未工作时仍保留原来的完整冷启动顺序。这是初始化阶段的一次查询，没有增加常驻轮询或固定等待。
5. 保留原子持久化、互斥锁、失败时恢复 AT 查询卡槽、数据手动关闭意图，以及 E5 家族现有默认射频策略。新增异步查询完成后再次检查允许位，避免覆盖期间保存的禁用操作。

## 验证范围

- E5 公共后端、上网卡切换及分卡显示：30 项离线测试通过。
- 从现有 OpenWrt ModemManager 1.24.0 构建树撤销旧策略补丁，再零 fuzz 应用新补丁；`git apply --check` 通过。
- 编译执行实际 C 回调与策略解析器，覆盖 32 组冷启动插卡／卡槽／允许位组合、逐步骤错误、0/2 回读、已供电与冷 SIM 恢复、活跃另一栈保护、AT 卡槽恢复、查询期间禁用和上下文释放。
- 本轮没有在设备部署或重新编译发行包；用户手工 AT 记录验证的是命令语义，不是新版后端、开机恢复和双卡隔离已完成实机验证。
