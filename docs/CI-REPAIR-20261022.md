## Follow-up: retain NCM flush retries

The author's Oct 22 E5 update fixes USB NCM transmit stalls when the queue is
temporarily out of USB requests. The current release branch builds its own
6.18 kernel from `linux-lts-e5` and applies the shared kernel policy adapters,
so the new NCM helper was added to that exact build path. Its regression test
compiles the real `f_ncm.c` timer and `u_ether.c` queue callbacks, covers 10,000
busy retries and a successful completion, and verifies that the old callback
reproduces the lost-flush failure. The firmware build now runs this test before
compilation. No modem, screen or user-data settings are changed by this kernel
patch.
