# T551M 手动主机＋外部 5V 受电

## 模型边界和依据

- 复用所连 T551M 的运行设备树与既有内核适配：MUSB 控制器、UMP9620
  Type-C @380，以及 Type-C 指向的实际 VBUS GPIO。没有套用 41S 的 DWC3。
- BQ2560x 实机寄存器标识 0x12、I2C 地址 0x6b；既有适配依据原厂
  `Enceka/kernel_sprd_ums9158` 固定提交 `63b8011056a5060e274fc1dcc9051c94d9a7bab8`
  并结合该机原驱动的电流编码。本次不修改芯片驱动、DT 电流表和 JEITA。
- 当前基带报告 `MOCORTM_V2_23B_W24.26.4_P9_Debug`，2024-10-25。
  基带有响应，但两槽报告未插 SIM；不把本轮检查记为蜂窝上网验证。
- 这是额外的手动模式，不声称原厂提供了相同的扩展坞操作。

## 接入方式

共享的 `devices/common/musb-host-sink.py` 接管 E5 已验证的 Type-C、PHY、
MUSB 逻辑，芯片差异通过显式参数选择。E5 的 AW32257 需要修正未知电源
会话的在线报告；T551M 的 BQ2560x 已读 REG08[2] Power Good，保持原实现。
正常供电 OTG 与自动模式沿用原路径，不增加常驻轮询，不直接强制 CE 或电流。

T551M 的构建入口显式传入 `--host-sink`。T512N 不通过父准备器隐式启用；
后续在自己的准备器中独立接入，见 `T512N-HOST-SINK-20261022.zh-CN.md`。
M8、K1 和远航 41S 不随此次 MUSB 接入改变。
网页、屏幕均复用已有能力检测，不按机型硬编码显示；重启恢复自动策略，
不允许将这个手动实验模式保存为开机自动应用。

## 软件与部署检查

- 完整 Image 和配套模块编译通过，原有 FGU、JEITA 与容器支持校验通过。
- C 回归覆盖实际外部电源/CC/检测完成、离线退出、旧供电主机退出、
  HOST_IDLE 接续、用户禁用数据和升压竞态；另验证 BQ 在线读取与总线错误，
  以及适配器重复运行不更改 BQ 驱动。E5 的 AW 分支单独回归。
- 原有根集线器生命周期、BC1.2 重启、共享 USB 后端回归通过。
- 动态解析 Linux boot 槽位，保留原启动参数、initramfs 其他内容及诊断尾部；
  写入及回读校验通过，Android boot 整体 SHA-256 写入前后相同。未写物理 NV。
- 新启动 USB NCM、热点正常，共享 USB 接口返回 `host-sink` 能力。

## 物理验证状态

电脑实际 5V 供电下做了 12 秒对照，每秒均满足：`policy=host-sink`、
`role=host`、主机根集线器存在、`otg-vbus=disabled`、BQ online=1、Charging。
电池净电流 +326～358 mA，输入预算沿用 SDP 500 mA。对照结束后自动恢复
`auto/device`，NCM 重新连通，没有保存实验模式。

这证明当前电脑供电下数据主机与受电不互斥；没有接入扩展坞外设，不能据此
宣布扩展坞 Ethernet 或其未知电源分类下的充电已通过，等待实际接线结果。

本次未制作发布安装包。设备备份和原始回执位于忽略的
`work/t551m-host-sink-20261022/`，不提交设备标识或配置。

## 扩展坞结果与普通 OTG 回归

用户确认供电扩展坞的网口与充电可以同时使用。该轮日志确认 RTL8153 由
r8152 注册；约开机 170～185 秒，原有充电管理报告 UNKNOWN 电源、输入预算
1000 mA、充电设定 990 mA，电池净电流 +618～750 mA。预算不是实际 USB 测量值。

但用户随后发现普通主机无输出、自动 OTG 不工作，不能据扩展坞通过宣布整体
功能完成。约 187 秒退出外部受电主机后，MUSB 在 RUNTIME_SUSPENDING 持续
等待；207～225 秒多次收到真实 HOST 接入，却没有再次执行 host start。
因此这轮首要故障位于退出/休眠交接，尚未走到开启 boost。

静态回归复现了核心独立会话 PM 引用没有释放的缺口：USB 核心的会话中断
工作曾在 SESSION=1 时 get 一个引用；HCD 移除清零 DEVCTL 并停中断，缺少
最后一次检查时，glue 只 put 自己的引用，剩余引用使 parent 无法休眠。
修正是在 SPRD HCD 清理后调度并同步完成既有会话检查，再允许函数返回；
既不篡改引用计数，也不在对象释放后遗留异步工作。非 SPRD 路径保持不变。

新增 C 回归使用实际会话检查、stop、HCD cleanup 函数，覆盖三次连续角色周期、
重复清理不重复 put、非 SPRD 不调度，以及移除修正后引用泄漏的反例。
修正版已完整编译并部署到当前 T551M，boot 回读和配套模块校验通过，
Android boot 哈希仍不变。新 boot SHA-256 为
`85a2104a3bd8ad379ba2b21f349ddfe7b5f55ac9c7dab701ee7a7895e34eaa4c`，
完整模块包 SHA-256 为
`e6900e41bf854dcd2ba54b07f39b6d0d312a9fe82a1199d054f188986cbfb9de`。
启动后默认 auto、NCM 正常；后续三种模式的实物结果见下节。

## 修正后三种模式实物通过

用户明确确认自动 OTG、手动主机、主机＋外部供电三种模式均正常。
接回电脑后读取的同一启动日志显示：

- 57.58 秒普通主机 `external=0`，执行 regulator enable，RTL8153 注册成功。
- 100.89 秒退出普通主机，101.76 秒完成控制器运行时休眠，没有持续卡住。
- 105.39 秒进入 `external=1`，未执行本机升压使能；网卡再次注册。
  110.16 秒充电管理报告 Charging，电池净电流 **+651 mA**，
  UNKNOWN 电源输入预算 1000 mA，充电设定 990 mA。
- 114.45 秒退出受电主机，115.31 秒完成运行时休眠；119.88 秒再次进入
  普通主机，升压使能、RTL8153 注册均成功，证明退出后普通 OTG 已恢复。
- 129.36 秒退出最后一轮主机，130.10 秒完成休眠；接回电脑后为 auto/device、
  NCM，最后读取电池净电流 +352 mA，沿用电脑 SDP 500 mA 预算。

日志中的短暂“waiting glue suspended”均在不足一秒后结束，符合已有自动休眠
延时，不再是旧版持续数十秒且阻止新主机启动的等待。未发现内核 Oops、BUG、
panic 或未知符号。原始回执保存在忽略目录的 `three-modes-confirmed.txt`。

本轮确认此 T551M 与该扩展坞/网卡组合能正常切换三种模式。未将此结论扩大
为长期负载、多型号扩展坞或其他机型的物理验证，也未制作发布安装包。
