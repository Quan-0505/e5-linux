# 2026-10-18 至 2026-10-19 累计更新：E5 / T551M / M8 / T512N

范围：`feat/t512n-bringup` 上北京时间 10 月 18 日 00:00 至 10 月 20 日 00:00 前的全部 6 条提交，含代码、适配、安装、构建和文档。按用户能感知的功能整理，文末列出每条提交的覆盖位置；不是仅列最后一次提交。

## 新增 T512N / PB8 机型适配

- 新增独立 T512N 设备配置，使用本机 Android 512NCA05 的设备树、驱动、固件和运行库，接入公共网页、实体屏幕、短信、通话、流量、SIM 管理及充电设置。
- 适配 320×480 显示、脉冲背光和 FT6336U 触摸。息屏／亮屏按直接触摸设备属性发现触控，不再写死 TLSC6x 驱动名称，其他机型也使用公共识别方式。
- 适配本机 64 位厂商基带程序、NV 隔离工作副本和 AT 接入；保留本机频段能力，不复制 T551M 的 LTE 候选表或默认 152 模式。
- 按本机充电芯片的实际版本修正电流寄存器编码，保留原厂电池、OCV、温度和 JEITA 表；不使用 T551M 的不同芯片电流步长。充电能力声明不等于已经测得相同功率。
- 补齐三簇 CPU 调频、温控及经本机 SML 核验的电压偏移支持，实测正偏移和恢复零偏移。不默认降压，也不将其他固件的电压编码套用到本机。
- 安装器支持 T512N 型号校验、专属名称／默认 SSID，以及已具备 root 的工程版 adbd；FBE＋metadata 加密的 data 沿用离线分区、原厂重置后回 Android 续装的流程。
- 用户及实机已确认画面／触摸、提示音、OTG、热点负载、两卡拨号与切卡、短信、电话和系统往返可用；三簇温控与调压有回读验证。屏幕闪烁在原厂 Android 也存在，未冒充 OpenWrt 已修；Wi-Fi 高延迟和完整续航仍不能宣称解决。

## 低电量关机与电量状态

- 公共新增事件驱动的低电量正常关机接管，覆盖有电池的 E5、T551M、M8，并在 T512N 配置中接入。启动先订阅电源事件再读取状态，正常电量时不新增周期轮询。
- 优先采用驱动的有效 `Critical` 状态；只有确实缺少该属性时才使用有效 0% 且未在充电等条件。无效或读取失败的数据不当成 0%，保留各机型充电例外及欠压判断。
- 走正常 poweroff、停服务及卸载流程，不强制重启，不为显示好看而重置电量计或统一添加电压阈值。
- 排查并处理 T551M 充电后显示一直停在 0%：现场 FGU 仍在更新，但 charger-manager 的显示更新已停止。部署关机接管并正常重启后，显示更新恢复；没有强制校准或直接将 FGU 数值伪装成 UI 百分比。
- 上述恢复验证不等于完整电量估算已校准；低电量耗尽、完整充放电及续航尚未实测。

## SIM 识别、切卡与射频

- 修复早期 SIM 探测对 AT 回复分帧的处理，避免错误码跨读取片段时误判卡状态；保留 busy／未知与真正无卡的区别，命令序列不变。
- 修复切上网卡实际成功却报 `No such file or directory`：公共后端正确处理 WWAN 驱动切换时短暂消失的 sysfs 节点，网页和屏幕共用修复。T512N 已完成 SIM2→SIM1→SIM2 往返，并分别获取 IPv4。
- 分卡射频改为 `AT+SFUN=5` 关闭、`AT+SFUN=4` 开启；同步 ModemManager 的状态判断和初始化权限处理，区分仅关闭射频与尚未给 SIM 上电。仍按各卡权限执行，不强行打开另一卡。
- 保留 AT 所有者、回放和拨号顺序，以及用户手动关闭数据的选择；E5 仓库**不采用 MU300 默认关闭 SIM2**的策略。
- E5 系列新版射频控制的逐机硬件验证未全部完成；V50 的测试结果不能替代本仓库实测。

## 自动网络模式设置

- 提供「机型默认」「全制式自动（134，含 2G）」「自动选网（152，不含 2G）」；T551M 默认 152，E5、M8、T512N 默认 134，保留用户已选值。
- 入口移至「蜂窝 → 网络锁定 → 网络模式」，仅在自动模式时显示，补齐中文、英文、土耳其语说明。
- 解释双卡高延迟、卡顿和选网偏好的用途，不承诺某编号固定优先 n78；显式 4G／SA／NSA 设置不被这个选项覆盖。网页和屏幕沿用同一公共锁定后端。

## Wi-Fi 稳定性与兼容性

- 按原厂 Marlin3Lite 实现修正 3 MiB 拼接固件的选段：读取本机 eFuse 决定是否加载对应 XPE 变体，避免“固件文件相同，实际运行变体却不同”。普通单镜像和其他芯片保留原处理，失败不猜测选段。
- 补齐无线 station 加入／离开事件的实际长度、字节序和 IE 边界检查，减少异常或截短事件越界风险；AP 管理帧缺少信道时正确使用本 AP 有效信道。
- 公共热点配置关闭 U-APSD，兼容新装和保留旧配置的升级，不关闭 WMM，不改变信道、带宽或密码。
- 已知边界：U30 Air 曾观察到配置关闭但固件仍广播支持 U-APSD，不能单凭配置认为固件行为已彻底改变。T512N 固件选段修复已完成离线回归和四机模块编译，实际固件变体与延迟改善仍待逐机复测。
- 本仓库机型走 SDIO，未照搬 MU300 的 PCIe RX 队列修复，也未加入其 CPU0 禁用 idle 策略。没有把 MU300 的测试数值当作 E5 系列性能保证。

## CPU 逐核控制

- 网页 CPU 设置新增逐核心开关与开机自动应用，CPU0 保持在线，默认不主动关闭其他核心。
- 修复网页带会话字段时误报「CPU 核心配置无效」；核心开关与调频互斥，失败尝试回滚，整簇离线后保留已保存的频率配置。
- 公共内核明确启用 CPU 热插拔，并在构建时检查能力；缺少支持的旧内核需要配套更新 Image 和模块，不能只换网页。

## 安装、版本与构建

- 修复缩容准备标记后带 NUL 字节时误报「命令没有完成」，不再把已经成功的分区准备当作失败。
- 修复强制内核命令行隐藏引导器参数时的安装标记读取，按受限键名从原始设备树 bootargs 补读，保证离线分区准备和内置根分区选择被正确识别；不改变整机的板级命令行。
- 发布版本包含构建时间、源码提交及源码指纹，在包名、系统信息和安装器显示统一标识。没有恢复用户已取消的增量更新功能。
- 主线内核构建统一控制 LOCALVERSION，避免自动附加 `-dirty`、Git 哈希或 `+`；保留机型后缀，Image、模块和 modules_install 使用同一真实 release，不在打包后改模块目录或 vermagic。
- 修复内核配置合并时的工作目录／输出路径、hostapd／BlueZ 容器的宿主架构及空缓存准备、bootctl 文件归属，减少跨平台和非 root 构建失败。
- 同步安装器通知事件和辅助文件依赖。自动禁用 MTP 的功能严格只对 MU300 适配器生效，E5、T551M、M8、T512N 不执行此操作。
- 安装包继续包含 Windows、Apple Silicon macOS 安装器、Python 入口及指南；不预装 Docker 或 VPN。
